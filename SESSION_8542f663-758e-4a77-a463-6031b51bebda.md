## Remaining manual steps (user action required)

### 1. Enable Appointments in sandbox (blocks booking creation)

The error is `"Merchant not onboarded to Appointments"`. Toggling it in the developer console is not enough — it must be activated from within the seller dashboard:

1. Go to **developer.squareup.com** → your application → **Sandbox** tab
2. Under **Sandbox test accounts**, click **Open** (launches the full Square dashboard in sandbox mode)
3. Inside that dashboard → **Appointments** → subscribe / activate
4. Then **Appointments → Services → Custom Cake Order** → assign "Sandbox Seller" as team member

After this, re-run `scripts/test-all.ts` — all 9 checks should pass.

### 2. Set bakery phone number

In `.env.local`, replace `BAKERY_PHONE_NUMBER=+1XXXXXXXXXX` with Ony's real phone number (E.164 format: `+14031234567`). This is required for SMS delivery.

## Architecture notes

- `lib/square.ts` and `lib/sms.ts` are **server-only** — never import from client components
- SMS failure is non-blocking: caught and logged, booking still succeeds
- The `serviceVariationVersion` is fetched fresh on every booking create (one extra catalog API call), ensuring version drift never causes failures after catalog updates
- Idempotency key for customer create is `customer-<base64url(email)>` (deterministic, 24h Square window)
- Phone number is omitted from Square customer record if blank — handles cases where a customer doesn't provide one
